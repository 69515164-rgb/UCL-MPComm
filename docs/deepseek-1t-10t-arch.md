# DeepSeek 从 1T 到 10T：同一骨架，只加路由专家

同一套 V4-Pro 骨架从 1T 放到 10T，变的是路由专家个数、专家表容量和 640 GB 卡的下限。层数、隐藏维、每 token 激活的 49B、单 token 通信量和 1M 上下文的 KV 保持不动。1.6T 是论文原模型，其余档位是外推。

## 随规模变化的量

外推规则：层数 61、隐藏 7168、专家中间维 3072 不动，用路由专家个数把总参数对齐到该档。专家数取整数，总参数因此落在名义档位附近，不强制等于 10 的整数次幂。

| 档位 | 口径 | 总参数 | 路由专家 | 相对 1.6T 专家倍数 | 激活参数 | 激活比 | 路由专家 FP4 容量 | 640 GB 卡下限 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1T | 外推 | 9.996×10^11 | 235 | 0.61 | 4.9×10^10 | 4.90% | 0.473 TB | 1 |
| 1.6T | 论文，V4-Pro | 1.600×10^12 | 384 | 1 | 4.9×10^10 | 3.06% | 0.774 TB | 2 |
| 2T | 外推 | 1.999×10^12 | 483 | 1.26 | 4.9×10^10 | 2.45% | 0.973 TB | 2 |
| 4T | 外推 | 4.002×10^12 | 980 | 2.55 | 4.9×10^10 | 1.22% | 1.975 TB | 4 |
| 8T | 外推 | 7.999×10^12 | 1972 | 5.14 | 4.9×10^10 | 0.61% | 3.973 TB | 7 |
| 10T | 外推 | 1.000×10^13 | 2469 | 6.43 | 4.9×10^10 | 0.49% | 4.975 TB | 8 |

从论文的 1.6T 到外推的 10T：路由专家 384 增到 2469（×6.43），FP4 专家表 0.774 TB 增到 4.975 TB，卡下限 2 增到 8。激活参数停在 4.9×10^10，激活比从 3.06% 降到 0.49%。8T 的专家表是 3.973 TB，6 张卡装不下（6×640 GB = 3.84 TB），下限是 7 张；10T 才到 8 张。

## 各档保持不变的量

这些数来自 V4-Pro 论文（arXiv:2606.19348）。外推各档原样沿用。

| 项目 | 取值 |
| --- | --- |
| 层数 | 61 |
| 隐藏维 | 7168 |
| 专家中间维 | 3072 |
| 共享专家 | 每层 1 个，普通 SwiGLU |
| 每 token 激活的路由专家 | 6 |
| 前 3 层路由 | 按 token id 哈希；其后为 top-6 |
| 注意力 | 前 2 层 HCA，其后 CSA 与 HCA 交错 |
| CSA | 压缩比 m = 4，稀疏 top-k = 1024 条压缩 KV |
| HCA | 压缩比 m′ = 128 |
| 查询 | 128 头，头维 512，查询压缩维 1536 |
| 滑窗 | 128 |
| mHC | 残差扩张 4 |
| MTP | 深度 1 |
| 上下文 | 1M |
| 路由专家精度 | FP4 |
| 单 token 专家通信量 | 7.87×10^6 字节 |
| 1M 上下文 KV | 与 V4-Pro 相同。论文给出该点相对 V3.2 为 10% KV、27% 单 token 推理 FLOPs |

通信量按论文恒等式回推，不是另测的数：每个 token、每个专家为 3 × 隐藏 字节（FP8 dispatch 与 BF16 combine），再乘 6 个专家和 61 层。

```text
7.87×10^6 = 6 × 3 × 7168 × 61
```

KV 由层数、头维 512、m = 4、m′ = 128 和滑窗 128 决定。这几项不随总参数变化，所以 1M KV 在各档相同。

## 推演备注

**论文原值。** V4-Pro：1.6T 总参数，49B 激活，61 层，隐藏 7168，1 个共享专家加 384 个路由专家，中间维 3072，每 token 激活 6 个路由专家。V4-Flash：284B / 13B，43 层，隐藏 4096，256 个路由专家，中间维 2048，同样激活 6 个。论文写明未另给的设置沿用 V3，V3 词表为 129280。DeepSeek 没有发布 1T、2T、4T、8T、10T 这几个模型。

**参数恒等式（回推）。** SwiGLU 一个专家在全部层上的参数：

```text
单个路由专家 = 3 × 7168 × 3072 × 61 = 4.030×10^9
V4-Pro 路由专家 = 4.030×10^9 × 384 = 1.547×10^12
其余参数 = 1.600×10^12 − 1.547×10^12 = 5.260×10^10
```

5.260×10^10 含共享专家 4.03×10^9，以及注意力、mHC、词表和 MTP。激活侧：6 个路由专家为 2.418×10^10，加共享专家 4.03×10^9，再加每 token 都要算的注意力等，对上论文的 4.9×10^10。

各档总参数：

```text
总参数 = 路由专家数 × 4.030×10^9 + 5.260×10^10
激活参数 = 4.9×10^10
激活比 = 4.9×10^10 / 总参数
FP4 容量 = 路由专家数 × 4.030×10^9 × 1/2 字节
卡下限 = ceil(FP4 容量 / 6.40×10^11 字节)
```

640 GB 按十进制 6.40×10^11 字节计。非路由的 5.260×10^10 参数按 FP8 估算约 53 GB，各档都落在取整余量里，不改变上表的卡下限。1T 余量最小，单卡 640 GB 减去 0.473 TB 后仍有约 167 GB。

**为何只加专家数。** V3 到 V4-Pro：层数和隐藏不动，专家数与中间维各 ×1.5，每 token 激活专家从 8 降到 6，总参数 ×2.4，激活参数从 37B 到 49B（×1.3）。V4-Flash 到 V4-Pro：层数、隐藏、专家数、中间维一起加，总参数 ×5.6，激活参数 ×3.8。两步里激活倍数都低于总参数倍数，新增参数主要进专家表。主表沿这个方向，把 1T 到 10T 的增量全部记在专家个数上。

**另一案，不放进主表。** 若把 Flash 到 Pro 的四轴倍数再乘一次（层数 ×1.42、隐藏 ×1.75、专家数 ×1.5、中间维 ×1.5），得到约 87 层、隐藏 12544、576 个路由专家、中间维 4608，总参数约 1.6T × 5.59 ≈ 8.9T。激活参数会随层数、隐藏和中间维上升，单 token 通信量和 KV 也不再保持上表的常数。论文没有给出头数和压缩比随宽度变化的规则，这一案的注意力超参定不下来，所以主表不收。

**和部署的关系。** 10T 档路由专家 4.975 TB，8 张 640 GB 卡的下限来自专家表容量。每 token 仍只派 6 个专家，卡间通信量保持 7.87×10^6 字节。专家个数增加到 2469，变的是单卡上的专家槽位，不是每 token 的派发个数。论文对 V4-Pro 给出的重叠条件是峰值算力 / 链路带宽 ≤ 2 × 中间维 = 6144 FLOP/Byte。中间维保持 3072 时，这个平衡点不变。

# 逐包打散：NIC SRAM 被谁占用，代入场景后能不能打满

公式全部用 Markdown 代码块，不用 LaTeX。

先把 SRAM 账本摊开，再代入「800G / 2 km / 32K QP / 逐包打散」。窗口公式只在账本需要时出现。

---

## 0. 先记住三件事

1. **片上 SRAM 不是窗口专用内存。** 它同时养连接上下文、地址翻译、WQE、收包缓冲、发送在途表、乱序位图，以及（若硬件坚持按序 DMA）乱序 payload 缓冲。后两项才是逐包打散真正要问的。
2. **商用 RNIC 是「Host ICM + 片上 cache」，不是「32K 条状态全上片」。** 能建 32K QP，只表示 Host 里有 32K 份表项；片上同时热的只有几百到几千。
3. **发窗计数几乎不占 SRAM；收窗位图占一点；乱序 payload 缓冲大到不能上片。** 所以「能不能打满」取决于：付完固定开销后还剩多少给位图，以及位图是 32K 静态均分，还是只给当前乱序的活跃 QP。

---

## 1. 哪些资源会占用 NIC SRAM

公开拆分主要来自 SRNIC（NSDI’23）对 RDMA 概念模型的枚举，以及它对 CX-4/5 的引用：片上约 **2 MB**，每个 RC QPC 约 **256–375 B**。CX-6/7 可建 128K QP，但片上仍是 cache，多了就走 Host ICM + PCIe。

### 1.1 七类资源

按「跟谁涨、能不能离开片上」分成七类。

| 编号 | 资源 | 存什么 | 跟谁涨 | 商用卡通常放哪 | 逐包打散关不关心 |
| --- | --- | --- | --- | --- | --- |
| A | 端口收包缓冲 | 吸收端口与后续流水线的瞬时差 | 端口速率 × 吸收时间，几乎不跟 QP 数涨 | **必须片上** | 否。这是端口税，先扣掉 |
| B | 连接上下文 QPC / CQC / EQC | SQ/RQ 指针、PSN、窗口/速率、CQ/EQ 映射 | **QP / CQ / EQ 条数** | Host ICM，片上只 cache 热连接 | 间接关心：它先吃掉大部分 cache |
| C | 地址翻译 MTT / MPT | VA → PA、权限 | **注册内存 / 页大小**，不跟 QP 数涨 | Host 全表，片上 cache | 否。但和 QPC 抢同一块 SRAM |
| D | WQE cache | 已取回、尚未完成的 Send/Recv WQE | 活跃 QP × 每 QP 缓存条数 | 活跃 QP 才 cache；全静态上片会爆 | 否。集合通信活跃 QP 少时很小 |
| E | 发送窗口计数 | `snd_una / snd_nxt / cwnd` | 每 QP 几个字 | 塞进 QPC，几乎免费 | 是，但 **不是 SRAM 瓶颈** |
| F | 发送在途表 ORT | 每个在途包的 PSN / MSN / 偏移，约 16–24 B/包 | 活跃 QP × 发送窗口包数 | 全量静态上片不可能；活跃集或 Host | 是。选择性重传需要，但仍远小于 payload |
| G | 接收乱序状态 | 位图（谁到了）+ 可选的 payload 重排缓冲 | 位图：`W_r` bit/QP；缓冲：`W_r * P` 字节/QP | 经典 RoCE 几乎不备大窗；IRN 式要五张 BDP 位图 | **是。这是打散能否打满的分界** |

SRNIC 概念模型还单列了「Reordering Buffer」：若硬件必须按序再 DMA 到 Host，每个乱序 QP 要一块 **BDP 大小的 payload 缓冲**。它比位图贵三个数量级，单独看下一小节。

### 1.2 三类缩放，决定谁贵

```
# 端口级（先缴的税）
M_rxbuf  ≈ B * T_absorb

# 连接级（跟创建了多少 QP 涨，不是跟打散涨）
M_qpc    = N_qp * S_qpc          # S_qpc ≈ 256–375 B（商用）
M_wqe    = N_act * N_wqe * S_wqe # S_wqe ≈ 64 B，N_wqe ≈ 8

# 在途包级（跟 BDP / 乱序深度涨，打散才把它放大）
M_ort    = N_act * W_s * 24
M_bitmap = N_slot * W_r / 8      # N_slot = N_qp（静态）或 N_ooo（共享池）
M_reord  = N_slot * W_r * P      # 按序 DMA 才需要；OOO 直接落位则为 0
```

同一场景里，`M_reord` 比 `M_bitmap` 大约大 `8P` 倍（`P ≈ 4176` 时约 **3.3 万倍**）。所以：

- 位图：可能挤进片上，但是否够用取决于怎么分。
- payload 重排缓冲：不能按 QP 静态上片，只能 OOO 直接 DMA 到 Host，或做很小的共享池。

### 1.3 商用卡真实模型：不是「32K 全上片」

```
Host DRAM (ICM)
  QPC 全表、CQC、MTT 全表、WQE、CQE
        ^
        | cache miss → PCIe 读 Host（约 1–2 us）
        v
片上 SRAM（数 MB）
  QPC cache + MTT cache + 收包缓冲 + 少量 WQE + （若有）窗口位图
```

公开数字：

- CX-5 片上约 **2 MB**，QPC 约 **375 B**。若 2 MB 全给 QPC，理论能热约 5.6K 条；实测吞吐从约 256 QP 就开始掉，16K 时 CX-6 从 97 Gb/s 掉到 52 Gb/s。说明 SRAM 还要分给 MTT / WQE / 缓冲，热连接远小于「2 MB / 375 B」。
- SRNIC 自己的 10K QP 概念模型（若全上片、100G、40 us RTT）如下，用来标定「每类有多贵」，不是 CX 的实物拆分。

| 资源（SRNIC 10K QP 概念模型） | 全上片要多少 | 他们怎么处理 |
| --- | ---: | --- |
| 收包缓冲 | 0.6 MB | 留片上 |
| QPC（他们按 210 B/QP） | 2.0 MB | 留片上 |
| MTT（4 GB MR、4 KB 页） | 8 MB | 改 1.2 MB cache |
| WQE cache（每 QP 8 条 × SQ+RQ） | 9.8 MB | 去掉，改无 cache 调度 |
| IRN 式 5 张 BDP 位图 | 3.0 MB | 卸载到 Host |
| 发送在途表 ORT | 114.4 MB | 改头字段后去掉 |
| 每 QP 一块 BDP 重排缓冲 | 4.9 GB | 改头字段 + OOO 落位后去掉 |

读这张表只需记住顺序：

```
重排缓冲 >> 发送在途表 >> WQE cache ≈ MTT 全表 > QPC > 位图 > 收包缓冲 > 发窗计数
```

800G 代 NIC 的片上容量没有公开数字。下面整卡按 **4–16 MB**、扣掉 A/B/C/D 之后能给窗口的按 **0.5 / 1 / 2 MB** 三档来算。这是外推，不是厂商规格。

## 2. 场景参数（后面所有代入只用这一组）

```
B      = 800 Gbit/s = 100 GB/s
P      ≈ 4176 B          # 4 KB 载荷 + 约 78 B 头
t_pkt  = P / B ≈ 41.8 ns
N_qp   = 32768
v      ≈ 2e8 m/s         # 光纤约 5 us/km
```

端到端时延和 BDP（**共同走线只加时延，不加乱序**）：

```
D      = D_prop + D_ser + D_sw + D_nic + D_q
D_prop = d / v
RTT    ≈ 2 * D
N_BDP  = ceil(B * RTT / P)
```

| 口径 | 单向光路 | 加 NIC/交换约 4 us 后的 RTT | N_BDP | BDP 字节 |
| --- | ---: | ---: | ---: | ---: |
| 2 km 端到端 | 10 us | 28 us | 670 包 | 2.80 MB |
| 2 km 是 L1–L2 一跳（来回各 2 km） | 20 us | 48 us | 1149 包 | 4.80 MB |

乱序只看同 QP 的路径差 `dt`，不看园区最长光纤：

```
dt = dd/v + dD_sw + dD_q
```

单流打满 800G 时，只为吞掉乱序所需的收窗：

```
W_r(dt) = ceil(dt / t_pkt) + 1
```

| dt | 只要吞乱序的 W_r |
| ---: | ---: |
| 0.5 us | 13 |
| 2 us | 49 |
| 5 us | 121 |
| 10 us | 241 |
| 20 us | 480 |

同时不欠吞吐、尾包还能滑窗，收窗还要盖住 BDP：

```
W_s  >= N_BDP                         # 单流打满
W_r  >= max(W_s, ceil(B_qp * dt / P) + 1)
     >= N_BDP + N_dt                  # 选择性重传的常用取法
```

集合通信里真正抢带宽的是 `N_act`（几十到几百），不是 32K。SRAM 必须按「少数 QP 接近线速」估，不能按 32K 均分带宽估。

```
# 反例：32K 均分时每条几乎不需要窗口
B_qp            = 800 Gbit/s / 32768 ≈ 24.4 Mbit/s
N_BDP_qp(28 us) ≈ 0.085 包
```

## 3. 把七类资源代入本场景

下面三列对照：

- **创建 32K**：表项建出来了，但不都热。
- **1 条 QP 打满 800G 并逐包打散**：窗口最苛刻。
- **256 条活跃**（集合通信更常见）：端口均分，每条约 3.125 Gb/s。

未标注的窗口按 `RTT = 28 us`、`N_BDP = 670`。4 km / 48 us 在括号里给一档。

### 3.1 A. 端口收包缓冲（先扣的税）

```
M_rxbuf ≈ B * T_absorb
```

| 吸收时间 | 字节 |
| ---: | ---: |
| 1 us | 100 KB |
| 5 us | 500 KB |
| 6 us（SRNIC 0.6 MB 那一档） | 600 KB |

800G 上这块仍然是几百 KB 量级，必须留片上，但 **不是打散的瓶颈**。账本里先划走 **0.5–0.6 MB**。

### 3.2 B. QPC / CQC（连接税，和打散无关，但先占 cache）

```
M_qpc_full = 32768 * 375 B = 12.0 MB
```

12 MB 已经大于整卡公开的 2 MB，也大概率大于 800G 代能匀给 QPC 的 cache。所以：

```
片上热 QP 数 ≈ M_qpc_cache / 375 B
```

| 匀给 QPC 的 cache | 大约能热多少 QP |
| ---: | ---: |
| 0.5 MB | ~1300 |
| 1.0 MB | ~2700 |
| 2.0 MB | ~5400 |

32K 能建，不等于 32K 能同时线速。QPC miss 一次就是一次 PCIe 往返，和窗口够不够是两件事；两边叠在一起才会掉吞吐。

CQC / EQC 比 QPC 小，但和 QPC 抢同一块 cache。账本里把它算进「连接 cache」，不再单列。

### 3.3 C. MTT / MPT（跟注册内存涨，和 QP 数无关）

```
M_mtt = (注册内存 / 页大小) * 8 B
```

| 注册内存 | 4 KB 页 | 2 MB 大页 |
| ---: | ---: | ---: |
| 4 GB（SRNIC 例子） | 8 MB | 16 KB |
| 1 TB（训练机更常见） | 2 GB | 4 MB |

全表只能在 Host。片上是 cache。大页几乎是必选项，否则 MTT 会把 QPC 一起挤下去。  
**对打散：不决定窗口宽度，但决定「窗口预算还剩多少」。**

### 3.4 D. WQE cache（只跟活跃 QP）

```
M_wqe = N_act * 8 * 64 B     # 每 QP 缓存 8 条 64 B WQE
```

| 范围 | SQ 一侧 | SQ+RQ |
| --- | ---: | ---: |
| 1 条活跃 | 0.5 KB | 1 KB |
| 256 条活跃 | 128 KB | 256 KB |
| 32K 全静态 | 16 MB | 32 MB |

32K 全静态上片不现实。256 条活跃只要几百 KB。**不是打散瓶颈。**

### 3.5 E. 发送窗口计数（几乎免费）

每 QP 三个到四个 32/64-bit 计数器，约 32 B，塞进 QPC：

```
32 K * 32 B ≈ 1.0 MB     # 若硬要静态全上片
1 条活跃 ≈ 32 B          # 实际开销
```

单流要填满管道：

```
W_s >= N_BDP
     = 670   （28 us）
     = 1149  （48 us）
```

计数器设成 670 或 1149 **不增加 SRAM**。  
**结论：发窗在 SRAM 意义上永远够。**

### 3.6 F. 发送在途表 ORT（选择性重传才需要，按「活跃 × 窗口」涨）

```
M_ort = N_act * W_s * 24 B
```

| 范围 | W_s = 670（28 us） | W_s = 1149（48 us） |
| --- | ---: | ---: |
| 1 条打满 | 16 KB | 27 KB |
| 256 条，每条窗口按均分后的 BDP | 约 16 KB 总量 | 约 27 KB 总量 |
| 32K 每条都按端口 BDP 静态建 | 524 MB | 900 MB |

只有「32K 条每条都按满端口 BDP 建 ORT」会爆。实际只给活跃 QP 建，或卸到 Host。  
**贵，但比 payload 重排小四个数量级；不是本场景的第一约束。**

### 3.7 G. 接收乱序：位图便宜，payload 缓冲极贵

**位图**（每包 1 bit）：

```
M_bitmap = N_slot * W_r / 8
```

**payload 重排缓冲**（每包整包拷一份）：

```
M_reord = N_slot * W_r * P
```

代入 `W_r = N_BDP`（单流要打满时的下限）：

| 结构 | 1 条 QP、W_r=670 | 1 条 QP、W_r=1149 | 32K 条各一张同样宽的窗 |
| --- | ---: | ---: | ---: |
| 位图 | 84 B | 144 B | 2.75 MB / 4.7 MB |
| payload 重排 | **2.80 MB** | **4.80 MB** | **90 GB / 157 GB** |

因此本场景里接收侧只能这样选：

1. **OOO 直接按 PSN 落到 Host 缓冲区**（`M_reord = 0`）。片上只留位图。这是「SRAM 还够讨论窗口」的前提。
2. **片上按序重排再 DMA**。单流打满就要 2.8–4.8 MB payload SRAM，几乎吃光整卡；32K 静态更不可能。

经典 RoCE 走 Go-Back-N、要求按序，就是为了不养 G。逐包打散一旦允许超窗乱序，必须走 1，否则还没问位图就先输在重排缓冲上。

## 4. 付完税之后，窗口只剩多少，怎么分

把必须先留下的扣掉，剩下才是窗口预算 `M_win`：

```
M_win = M_sram
      - M_rxbuf          # A，约 0.5–0.6 MB
      - M_qpc_cache      # B
      - M_mtt_cache      # C
      - M_wqe_hot        # D，活跃集通常 < 0.3 MB
```

800G 代没有公开 `M_sram`。下面把 **能给位图的预算** 直接取三档：`M_win = 0.5 / 1.0 / 2.0 MB`。这已经假设重排缓冲为 0、ORT 不静态铺 32K。

### 4.1 方案 A：32K 条各分一张同样宽的位图

```
W_r_max = 8 * M_win / N_qp
```

| M_win | 每 QP 的 W_r | 单流 800G 能扛的 dt | 相对 28 us BDP（670 包） |
| ---: | ---: | ---: | ---: |
| 0.5 MB | 128 | 5.3 us | 19% |
| 1.0 MB | 256 | 10.7 us | 38% |
| 2.0 MB | 512 | 21.4 us | 76% |

发窗可以仍是 670 / 1149，SRAM 不管它。  
收窗 128–512 **小于端口 BDP**，单流填不满管道。

收窗不够时，端口被窗口卡住：

```
B_cap = W_r * P / RTT
```

`M_win = 1 MB`、`W_r = 256`：

```
RTT = 28 us  →  B_cap = 256 * 4176 / 28e-6 = 38.2 GB/s = 306 Gbit/s   # 38% 线速
RTT = 48 us  →  B_cap = 256 * 4176 / 48e-6 = 22.3 GB/s = 178 Gbit/s   # 22% 线速
```

32K 均分带宽时，每条只要零点几个包的窗，方案 A **也能打满端口**。  
它打不满的是：**少数 QP 独占 800G + 逐包打散**。

### 4.2 方案 B：共享位图池（只给当前乱序的 QP）

```
M_pool ≈ N_ooo * W_r / 8
W_r    = N_BDP + N_dt
```

取 `W_r = 1024`（盖住 48 us BDP + 约 10 us 乱序）：

```
每 QP 位图 = 1024 / 8 = 128 B
1 MB 池   → 同时乱序的 QP 数上限 = 8192
```

集合通信同时乱序的通常是几十到几百条，池是够的。此时：

```
W_s = W_r = 1024 >= N_BDP
```

**单流可以打满 800G**，条件是 `N_ooo` 不超过池深。

### 4.3 方案 C：位图在 Host（SRNIC 一类）

片上几乎只留 QPC / MTT cache。32K QP 能建。每个乱序包可能要 PCIe 读 Host 位图：

```
PCIe 往返 ≈ 1–2 us
800G * 2 us = 25 KB ≈ 6 个包的气泡
```

偶发乱序可以打满；持续逐包打散时，Host 位图路径会把 800G 吃出气泡。

## 5. 代入后的判定（只看这一张表）

前提：选择性重传 + OOO 直接落位（方案 G 选 1，不在片上堆 payload）。

| SRAM 用法 | 32K QP 均分端口 | 1 条或少数 QP 线速 + 逐包打散 | 卡在哪一类资源 |
| --- | --- | --- | --- |
| 静态 32K 张 128–256 bit 位图 | 能打满 | 不能（约 22%–38% 线速） | G 位图均分后 `W_r < N_BDP` |
| 约 1 MB 共享 BDP 位图池 | 能打满 | **能打满** | G 够；A–F 按活跃集都不大 |
| 位图在 Host | 能打满 | 持续打散时危险 | G 的访问延迟，不是容量 |
| 经典 RoCE GBN，片上无 OOO 窗 | 有序 ECMP 时能 | 不能（超窗即重传塌缩） | 根本没有 G |
| 片上按序重排 | 不能按 32K 建 | 单流就要 2.8–4.8 MB payload | **G 的重排缓冲** |

三条验收语句：

1. **只问「32K 条同时有活、端口打满」**：窗口不是瓶颈。QPC/MTT cache miss 才是。
2. **问「逐包打散，还允许单 QP / 少 QP 跑满 800G」**：静态 32K 均分位图不够；要共享池，或把真正活跃的 QP 限制在几百以内并给它们 BDP 级收窗。
3. **2 km 走线**：只把 RTT / BDP 从 670 加到约 1150（若 2 km 是 L1–L2 一跳）。它不加乱序。乱序预算仍按 `dt` 单给。

工程上共享池的验收式：

```
W_r_shared >= B * RTT / P  +  B * dt_p99.9 / P
```

800G、`RTT = 28 us`、`dt_p99.9 = 10 us`：

```
W_r >= 670 + 240 = 910 包
```

1 MB 共享池按 1024 bit/QP，可同时撑约 8000 条乱序连接，集合通信够用；32K 条各静态 256 bit，不够撑线速逐包打散。

## 6. 公式速查

```
# SRAM 账本
M_rxbuf   ≈ B * T_absorb
M_qpc     = N_qp * S_qpc                 # S_qpc ≈ 375 B
M_mtt     = (注册内存 / 页大小) * 8
M_wqe     = N_act * N_wqe * 64
M_ort     = N_act * W_s * 24
M_bitmap  = N_slot * W_r / 8
M_reord   = N_slot * W_r * P             # OOO 落位则 = 0
M_win     = M_sram - M_rxbuf - M_qpc_cache - M_mtt_cache - M_wqe_hot

# 时延
D      = D_prop + D_ser + D_sw + D_nic + D_q
D_prop = d / v                           # v ≈ 2e8 m/s
RTT    ≈ 2 * D
dt     = dd/v + dD_sw + dD_q             # 乱序只看路径差

# 窗口
t_pkt         = P / B
N_BDP         = ceil(B * RTT / P)
W_s           >= N_BDP                   # 单流打满；计数器几乎不占 SRAM
sum_i W_s(i)  >= N_BDP                   # 端口级
W_r           >= max(W_s, ceil(B_qp * dt / P) + 1)

# 可达带宽
B_achieved = min(B,  W_s * P / RTT,  W_r * P / dt)
```

# N+2：20T DeepSeek SLO 详细计算过程

这份是演算稿。结果摘要在 `deepseek-20t-n2-slo.md`，幻灯片在 `deepseek-20t-n2-slo.pptx`。三份用的是同一套式子。

单位按十进制：1 GB = 10^9 字节，1 TB = 10^12 字节。HBM、DDR5 的标称已经是字节每秒。H2D、D2D、参数面、机内 P2P、总线 DDR 池的标称是比特每秒，先除以 8 再乘效率。一份副本是 256 卡。单条请求不跨副本，所以副本个数不改变单条 TTFT 或 TPOT。

要满足的三条是：命中 99.5% 时 TTFT ≤ 10 秒，TPOT ≤ 10 毫秒，TPOT ≤ 30 毫秒。输入取 64K、128K、256K、512K、1M、2M、4M，都是 1024 的幂。输出 512 token 只用来把 Prefill 和 Decode 的请求/秒对齐。

## 2. 从 1.6T 推到 20T

V4-Pro 论文是 1.6×10^12 参数、384 个路由专家、61 层、隐藏 7168、专家中间维 3072、每 token 激活 6 个路由专家、激活参数 4.9×10^10。20T 没有发布。外推只改路由专家个数，其余骨架不动。

一个路由专家是 gate、up、down 三个矩阵，61 层各一份。

```text
3 × 7168 = 21,504
21,504 × 3072 = 66,060,288
66,060,288 × 61 = 4,029,677,568
```

1.6T 去掉 384 个路由专家，剩下共享专家、注意力、词表、mHC、MTP。

```text
384 × 4,029,677,568 = 1,547,396,186,112
其余 = 1,600,000,000,000 − 1,547,396,186,112 = 52,603,813,888
```

把总参数对齐到 2×10^13，专家数向上取整。

```text
(2e13 − 52,603,813,888) / 4,029,677,568 = 4950.122150
E = ceil(这个数) = 4951
总参数 = 4951 × 4,029,677,568 + 52,603,813,888 = 20,003,537,453,056
比 2×10^13 多 3,537,453,056
```

激活参数不随专家个数增加。6 个路由专家加 1 个共享专家，剩下的差额是每 token 都要算的注意力等项，用来对上论文的 4.9×10^10。

```text
6 × 4,029,677,568 = 24,178,065,408
共享专家 = 4,029,677,568
其余激活 = 4.9e10 − 7 × 4,029,677,568 = 20,792,257,024
激活参数 = 24,178,065,408 + 4,029,677,568 + 20,792,257,024 = 49,000,000,000
1.6T 激活比 = 4.9e10 / 1.6e12 = 3.06%
20T 激活比 = 4.9e10 / 20,003,537,453,056 = 0.245%
```

路由专家用 FP4，一个参数 0.5 字节。共享专家和注意力用 FP8，一个参数 1 字节。

```text
FP4 专家表 = 4951 × 4,029,677,568 × 0.5 = 9,975,466,819,584 字节 = 9.975467 TB
```

## 3. 一个 token 的 KV

61 层里 30 层 CSA、31 层 HCA。CSA 压缩比 4，另有 64 字节索引。HCA 压缩比 128。K/V 已经合成 576 字节的 latent，不再乘 2。滑窗 128，输入不短于 128 时，滑窗字节是常数。

```text
CSA 每 token = 576/4 + 64/4 = 144 + 16 = 160 字节
30 层 CSA = 30 × 160 = 4,800 字节
HCA 每 token = 576/128 = 4.5 字节
31 层 HCA = 31 × 4.5 = 139.5 字节
每 token = 4,800 + 139.5 = 4,939.5 字节
滑窗 = 61 × 128 × 576 = 4,497,408 字节
一条序列存量 K(S) = 4939.5 × S + 4,497,408
```

| 输入 | token | 一条序列字节 | 一条序列 |
| --- | --- | --- | --- |
| 64K | 65,536 | 328,212,480 | 0.3282 GB |
| 128K | 131,072 | 651,927,552 | 0.6519 GB |
| 256K | 262,144 | 1,299,357,696 | 1.2994 GB |
| 512K | 524,288 | 2,594,217,984 | 2.5942 GB |
| 1M | 1,048,576 | 5,183,938,560 | 5.1839 GB |
| 2M | 2,097,152 | 10,363,379,712 | 10.3634 GB |
| 4M | 4,194,304 | 20,722,262,016 | 20.7223 GB |

Decode 一步的稀疏读比存量小。压缩历史全读索引或 HCA latent，CSA latent 只读选中的那部分。

```text
选中条数 = min(1024, S/4)
稀疏读 = 30×(S/4)×64 + 31×(S/128)×576 + 30×选中×576 + 4,497,408
```

## 4. 带宽怎么换成计时用的数

DDR5 的 2 TB/s 是每台 8 卡机器的字节带宽，用来替换原来的 1288.8 GB/s，容量仍是每机 768 GB。它已经是字节，不再除以 8。

| 项目 | 标称 | 换成字节 | 效率 | 计时值 |
| --- | --- | --- | --- | --- |
| FP4 算力 | 48 P = 4.8×10^16 FLOP/s | 字节口径，不除 8 | ×70% | 3.3600e+16 FLOP/s = 33.60 P |
| HBM | 33 TB/s，640 GB | 字节口径 | ×80% | 2.6400e+13 B/s = 26.40 TB/s |
| H2D | 每卡单向 1.6 Tb/s | 1.6e12/8 = 2.00e11 B/s | ×80% | 1.6000e+11 B/s = 160 GB/s |
| DDR5 | 每机 2 TB/s，768 GB | 2e12 B/s 已是字节 | ×80% 后 /8 卡 | 2.0000e+11 B/s = 200 GB/s，每卡 96 GB |
| H2D 换入 | H2D 与每卡 DDR 取更小 | min(160, 200) GB/s | 已含效率 | 1.6000e+11 B/s = 160 GB/s |
| D2D | 每卡单向 48 Tb/s | 48e12/8 = 6.00e12 B/s | ×80% | 4.8000e+12 B/s = 4.80 TB/s |
| 机内 P2P | 两卡之间 1.6 Tb/s | 1.6e12/8 = 200 GB/s 一条 | 7 条 ×80% | 1.1200e+12 B/s = 1.12 TB/s |
| 参数面物理 | 每卡 800 Gb/s | 800e9/8 = 1.00e11 B/s | 拉 KV 不再乘 80% | 100 GB/s |
| P→D | 同一条参数面 | 100 GB/s | ×80% | 80 GB/s |
| 拉 KV 基线 | 物理的 25% | 100 × 0.25 | 不叠乘 80% | 25 GB/s |
| 拉 KV NEW | 物理的 100% | 100 GB/s | 不叠乘 80% | 100 GB/s |
| 总线 DDR 池 | 每卡 51.2 Tb/s，容量不限 | 51.2e12/8 = 6.40e12 B/s | ×80% | 5.1200e+12 B/s = 5.12 TB/s |

AllReduce 用 1.12 TB/s，因为一卡到另外 7 卡的 P2P 可以同时用。7 × 200 GB/s = 1.40 TB/s，再乘 80% 得 1.12 TB/s。D2D 口是 6.00 TB/s，高于这 1.40 TB/s，所以不把 AllReduce 再截到交换平面上。

集合通信每层另加 5 微秒，61 层一共 0.305 毫秒的固定启动。这项加在对应的 AllReduce、dispatch、combine 里面，不和传输重叠。

## 5. 每卡放什么，KV 还剩多少

注意力 TP=8，一组 8 卡放一份注意力。MoE EP=256，专家摊满整个超节点。DP = 256/8 = 32。

```text
每卡路由专家 = 9,975,466,819,584 / 256 = 38,966,667,264 字节 = 38.9667 GB
每卡专家个数 = 4951 / 256 = 19.3398
每卡共享专家 = 4,029,677,568 字节 = 4.0297 GB
每卡注意力 = 1.935e10 / 8 = 2,418,750,000 字节 = 2.4188 GB
预留 = 6,000,000,000 字节 = 6.0000 GB
四项合计 = 51.4151 GB
每卡 KV 房间 = 640 GB − 合计 = 588.5849 GB
副本 KV 房间 = 256 × 588.5849 GB = 150.6777 TB
```

如果 EP 改成 16，路由专家只摊到 16 卡。

```text
每卡路由专家 = 9,975,466,819,584 / 16 = 623,466,676,224 字节 = 623.4667 GB
再加共享、注意力、预留后，KV 房间 = 4.0849 GB
4M 一条序列存量 = 20.7223 GB
```

EP=16 时每卡 KV 房间是 4.0849 GB，一条 4M 序列要 20.7223 GB。房间装不下这条序列，所以这份副本用 EP=256。EP 走 D2D 交换平面，不进参数面。

## 6. Prefill 的式子

全局批先按 DP=32 得到本地批 n。拉 KV 和注意力再按 TP=8 切开。n/8 = 全局批/256。

```text
TTFT = T_pull + max(T_HBM, T_compute) + T_AR + T_MoE + T_tail
T_pull = n × (p×4939.5 + 61×min(p,128)×576) / (8 × 拉KV带宽)
T_compute = n × (CSA索引 + HCA + CSA核心 + 投影) / (8 × 33.60 P × align(rows))
rows = n × q
align(rows) = rows / (ceil(rows/16) × 16)
T_AR = 61 × (5e-6 + 2×7/8 × rows × 7168 × 2 / 1.12 TB/s)
T_MoE = T_dispatch + max(T_weight, T_gemm) + T_combine
T_tail = max(0, T_PD − 主体×60/61)
T_PD = n × K(S) / (8 × 80 GB/s)
```

p = 0.995×S，q = 0.005×S。系统 Prefill TPS = 全局批 × S / 实际 TTFT。分子用完整输入，分母用摸高批的实际时间，这个时间可以略小于 10 秒。

批量从 1 开始倍增，再二分。返回的批满足 TTFT ≤ 10 秒，批加 1 则超过 10 秒。

### 6.1 64K 基线，批 139,712

输入 S = 65,536，全局批 = 139,712，拉 KV 带宽 = 25.0000 GB/s，命中 = 0.995.

本地批和 token 拆分：

```text
n = ceil(139,712 / 32) = 4,366
p = 0.995 × 65,536 = 65,208.3200
q = 0.005 × 65,536 = 327.6800
rows = n × q = 1,430,650.8800
16 行对齐后的行数 = 1,430,656
align = rows / 对齐行数 = 0.999996
```

一条序列要拉的 prefix KV：

```text
p × 4939.5 = 65,208.3200 × 4939.5 = 322,096,496.6400
滑窗 = 61 × min(p, 128) × 576 = 61 × 128 × 576 = 4,497,408
一条序列 = 326,593,904.6400 字节 = 0.3266 GB
T_pull = 4,366 × 326,593,904.6400 / (8 × 2.500000e+10)
       = 7.129545 秒 = 7129.545 毫秒
```

未命中段的注意力计算。context 是未命中 token 要看的历史对：先看已命中的 p，再看未命中段内部的三角。

```text
context = q×p + q×(q+1)/2 = 21,421,313.2288
CSA 索引 = 30 × 4096 × context = 2.632251e+12
HCA      = 31 × 2048 × context = 1.359996e+12
CSA 核心 = 30 × 262144 × (1024+128) × q = 2.968681e+12
投影     = 1.935e10 × 2 × q = 1.268122e+13
单条序列 FLOPs = 1.964214e+13
T_compute = n × FLOPs / (8 × 3.360e16 × align)
          = 4,366 × 1.964214e+13 / (8 × 3.360000e+16 × 0.999996)
          = 0.319040 秒 = 319.040 毫秒
```

HBM 上这一步要碰的字节是本卡注意力权重，加上本地 n 条序列的整段 KV 和未命中段新写的 KV，再除以 TP。

```text
一条序列存量 = 65,536 × 4939.5 + 4497408 = 328,212,480 字节 = 0.3282 GB
HBM 字节 = 1.935e10 / 8 + 4,366 × (328,212,480 + 327.6800 × 4939.5) / 8
        = 182,424,048,462.7200 字节 = 182.4240 GB
T_HBM = 182.4240 GB / 26.40 TB/s = 0.006910 秒 = 6.910 毫秒
max(T_HBM, T_compute) = 0.319040 秒 = 319.040 毫秒
```

AllReduce 走机内 7 条 P2P。每层字节是环上两趟，乘 (TP-1)/TP，隐藏 7168，BF16 两字节。每层另加 5 微秒。

```text
每层字节 = 2 × 7/8 × 1,430,650.8800 × 7168 × 2 = 35,892,169,277.4400
T_AR = 61 × (5e-6 + 35,892,169,277.4400 / 1.120e12) = 1.955146 秒 = 1955.146 毫秒
```

MoE 的 token 数是全局批乘未命中长度。热 token 在均值上加两个标准差，并且不超过全部 token×6。热专家用 1−exp(−6×token/E) 估计有 token 落到的比例，再加两个标准差。GEMM 行数按 16 对齐。6×隐藏×中间维是 3 个矩阵各算 2 次乘加。

```text
MoE token = 139,712 × 327.6800 = 45,780,828.1600
均值 = token × 6 / 256 = 1,072,988.1600
热 token = min(token×6, 均值 + 2×标准差) = 1,075,055.8126
有流量的专家比例 = 1 − exp(−6 × token / 4951) = 1.000000
每卡专家槽 = 4951 / 256 = 19.3398
热专家 = 19.3398
权重字节 = 热专家 × 4,029,677,568 × 0.5 + 共享专家 = 42,996,344,832
T_weight = 0.001629 秒 = 1.629 毫秒
GEMM FLOPs = (路由对齐行 + 共享对齐行) × 6 × 7168 × 3072 × 61 = 1.010746e+16
T_gemm = 0.300817 秒 = 300.817 毫秒
max(T_weight, T_gemm) = 0.300817 秒 = 300.817 毫秒
dispatch 字节/层 = 热 token × 7168 × 1 = 7,706,000,064.5880
combine  字节/层 = 热 token × 7168 × 2 = 15,412,000,129.1761
T_dispatch = 61 × (5e-6 + dispatch / 4.80 TB/s) = 0.098235 秒 = 98.235 毫秒
T_combine  = 61 × (5e-6 + combine  / 4.80 TB/s) = 0.196166 秒 = 196.166 毫秒
T_MoE = T_dispatch + max(T_weight, T_gemm) + T_combine = 0.595218 秒 = 595.218 毫秒
```

P→D 把整段 KV 送到 Decode。它和前面 60/61 层的主体重叠，只把超出的部分留在尾上。

```text
T_PD = 4,366 × 328,212,480 / (8 × 80 GB/s) = 2.239025 秒 = 2239.025 毫秒
主体 × 60/61 = 9.835032 秒 = 9835.032 毫秒
T_tail = max(0, T_PD − 主体×60/61) = 0.000000 秒 = 0.000 毫秒
```

加总：

```text
TTFT = T_pull + max(T_HBM, T_compute) + T_AR + T_MoE + T_tail
     = 7.129545 + 0.319040 + 1.955146 + 0.595218 + 0.000000
     = 9.998950 秒 = 9998.950 毫秒
系统 Prefill TPS = 139,712 × 65,536 / 9.998950 = 9.157128e+08 token/s
```

批 139,713 的 TTFT = 10.001111 秒 = 10001.111 毫秒，超过 10 秒。所以 139,712 是这个输入的最大批。

拉 KV 占 TTFT 的 71.30%。max(HBM, 计算) 取的是计算，HBM 是 0.006910 秒 = 6.910 毫秒，计算是 0.319040 秒 = 319.040 毫秒。尾部是 0，因为 P→D 的 2.239025 秒 = 2239.025 毫秒 短于主体的 60/61。

### 6.2 4M 基线，批 1,536

```text
context = q×p + q×(q+1)/2 = 87,741,038,382.2849

T_compute = n × FLOPs / (8 × 3.360e16 × align)
          = 48 × 1.735372e+16 / (8 × 3.360000e+16 × 0.999993)
          = 3.098899 秒 = 3098.899 毫秒
```

HBM 上这一步要碰的字节是本卡注意力权重，加上本地 n 条序列的整段 KV 和未命中段新写的 KV，再除以 TP。

```text
一条序列存量 = 4,194,304 × 4939.5 + 4497408 = 20,722,262,016 字节 = 20.7223 GB
HBM 字节 = 1.935e10 / 8 + 48 × (20,722,262,016 + 20,971.5200 × 4939.5) / 8
        = 127,373,855,034.2400 字节 = 127.3739 GB
T_HBM = 127.3739 GB / 26.40 TB/s = 0.004825 秒 = 4.825 毫秒
```

```text
每层字节 = 2 × 7/8 × 1,006,632.9600 × 7168 × 2 = 25,254,407,700.4800
T_AR = 61 × (5e-6 + 25,254,407,700.4800 / 1.120e12) = 1.375768 秒 = 1375.768 毫秒
```

MoE 的 token 数是全局批乘未命中长度。热 token 在均值上加两个标准差，并且不超过全部 token×6。热专家用 1−exp(−6×token/E) 估计有 token 落到的比例，再加两个标准差。GEMM 行数按 16 对齐。6×隐藏×中间维是 3 个矩阵各算 2 次乘加。

```text
MoE token = 1,536 × 20,971.5200 = 32,212,254.7200
均值 = token × 6 / 256 = 754,974.7200
热 token = min(token×6, 均值 + 2×标准差) = 756,709.1082
有流量的专家比例 = 1 − exp(−6 × token / 4951) = 1.000000
每卡专家槽 = 4951 / 256 = 19.3398
热专家 = 19.3398
```

## 8. Decode 的式子

```text
TPOT = T_SWAP + max(T_HBM, T_compute) + T_AR + T_MoE
稀疏读见第 3 节
本卡稀疏读 = n × 一条稀疏读 / 8
溢出比例 = max(全局批 × K(S) − 副本房间, 0) / (全局批 × K(S))
T_SWAP = 本卡稀疏读 × 溢出比例 / 换入带宽
T_HBM = (本卡稀疏读 + 注意力权重/8) / 26.40 TB/s
T_compute = n × (score + 投影) / (8 × 33.60 P × align(n))
```

换入带宽在基线里是 160 GB/s。每卡主机 DDR 还要装得下溢出的 KV，上限 96 GB。搜索在时间和容量里取同时满足的最大批。系统 Decode TPS = 全局批 / 实际 TPOT。

## 12. Case 2：160 GB/s 换入改成 5.12 TB/s 的池

池的标称是每卡 51.2 Tb/s。51.2e12 / 8 × 80% = 5.12 TB/s。容量不设上限，不经过 H2D，也不被 48 Tb/s 的交换平面截断。对照列仍是第 9 节的 160 GB/s。

### 12.1 4M、30 毫秒，池上的批 17,184

输入 S = 4,194,304，全局批 = 17,184，换入带宽 = 5,120.0000 GB/s。

一步 Decode 不读整段 KV。CSA 读压缩索引、最多 1024 条被选中的 latent，再加 128 token 的滑窗。HCA 按压缩比 128 读 latent。

```text
选中条数 = min(1024, S/4) = 1,024
CSA 索引字节 = 30 × (S/4) × 64 = 2,013,265,920
HCA latent   = 31 × (S/128) × 576 = 585,105,408
CSA 选中     = 30 × 1,024 × 576 = 17,694,720
滑窗         = 4,497,408
一条序列稀疏读 = 2,620,563,456 字节 = 2.6206 GB
本卡稀疏读 = n × 一条 / 8 = 537 × 2,620,563,456 / 8 = 175,905,321,984 字节
```

存量超过副本 KV 房间的比例记为溢出。换入只为这一比例付带宽。每卡落到主机 DDR 或 DDR 池的字节是溢出比例乘整段存量再除以 256。

```text
整段存量 = 17,184 × 20,722,262,016 = 356,091,350,482,944 字节 = 356.0914 TB
副本 KV 房间 = 150,677,735,723,008 字节 = 150.6777 TB
溢出比例 = max(存量 − 房间, 0) / 存量 = 57.6857%
每卡溢出 = 802.3969 GB
T_SWAP = 本卡稀疏读 × 溢出比例 / 换入带宽
       = 175,905,321,984 × 0.576857 / 5.120000e+12
       = 0.019819 秒 = 19.819 毫秒
```

注意力 FLOPs 用整段 S，不再用 Prefill 的未命中 context。核心项用选中条数加滑窗。

```text
score = 30×4096×S + 31×2048×S + 30×262144×(选中+128) = 7.907437e+11
再加投影 1.935e10×2 = 8.294437e+11
align(n) = 537 / 544 = 0.987132
T_compute = n × FLOPs / (8 × 3.360e16 × align) = 0.001679 秒 = 1.679 毫秒
T_HBM = (本卡稀疏读 + 注意力权重/8) / 26.40 TB/s = 0.006755 秒 = 6.755 毫秒
max(T_HBM, T_compute) = 0.006755 秒 = 6.755 毫秒
```

HBM 时间按整段稀疏读计，不把已经算进 T_SWAP 的那一比例扣掉。换入加在 max 的外面。

```text
每层 AllReduce 字节 = 2 × 7/8 × 537 × 7168 × 2 = 13,472,256
T_AR = 0.001039 秒 = 1.039 毫秒
MoE token = 全局批 = 17,184
热 token = 442.8088，热专家 = 19.3398
T_weight = 0.001629 秒 = 1.629 毫秒，T_gemm = 0.000168 秒 = 0.168 毫秒
T_dispatch = 0.000345 秒 = 0.345 毫秒，T_combine = 0.000386 秒 = 0.386 毫秒
T_MoE = 0.002360 秒 = 2.360 毫秒
```

```text
TPOT = T_SWAP + max(T_HBM, T_compute) + T_AR + T_MoE
     = 0.019819 + 0.006755 + 0.001039 + 0.002360
     = 0.029972 秒 = 29.972 毫秒
系统 Decode TPS = 17,184 / 0.029972 = 573,337.1743 token/s
```


## 13. 副本怎么配

一条请求在一个 Prefill 副本里做完输入，再在一个 Decode 副本里生成输出。输出按 512 token 计。一个 Prefill 副本每秒完成的请求数是 全局批 / TTFT。一个 Decode 副本每秒完成的请求数是 (全局批 / TPOT) / 512。

```text
64K，10 毫秒：Prefill 13972.67 请求/秒，Decode 24532.74 请求/秒，1.76 份 Prefill 配 1 份 Decode
64K，30 毫秒：Prefill 13972.67 请求/秒，Decode 28899.20 请求/秒，2.07 份 Prefill 配 1 份 Decode
4M，10 毫秒：Prefill 156.06 请求/秒，Decode 1440.25 请求/秒，9.23 份 Prefill 配 1 份 Decode
4M，30 毫秒：Prefill 156.06 请求/秒，Decode 498.40 请求/秒，3.19 份 Prefill 配 1 份 Decode
```

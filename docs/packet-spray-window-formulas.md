# 逐包打散：乱序接收窗口、发送窗口、带宽与端到端时延

本文给出「逐包打散且不欠吞吐」时的窗口/带宽/时延关系，并按典型商用 NIC SRAM、32K QP 并发、800G 端口、2 km 走线反推发送/接收窗口，判断能否打满端口。

公式全部用 Markdown 代码块书写，避免 LaTeX 渲染乱码。

---

## 1. 符号

| 符号 | 含义 |
| --- | --- |
| `B` | 端口有效吞吐，单位：字节/秒 |
| `P` | 线上包长（含以太网 / IP / UDP / RoCE 头），单位：字节 |
| `L` | 有效载荷，单位：字节 |
| `D` | 端到端单向时延 |
| `RTT` | 往返时延 |
| `dt` | 同 QP 多路径最大时延差（乱序的真正来源） |
| `W_s` | 发送窗口，单位：包数 |
| `W_r` | 接收乱序窗口（位图宽度），单位：包数 |
| `N_qp` | 并发 QP 数 |
| `N_act` | 同时真正占带宽的 QP 数 |
| `N_BDP` | 端口级带宽时延积，单位：包数 |
| `t_pkt` | 单包序列化时间 |

800G、4 KB 有效载荷、约 78 B 头时：

```
P      ≈ 4176 B
B      = 800 Gbit/s = 100 GB/s
t_pkt  = P / B = 4176 / 1e11 = 41.8 ns
```

## 2. 四个基本公式

### 2.1 端到端时延

```
D = D_prop + D_ser + D_sw + D_nic + D_q
```

其中光纤传播：

```
D_prop = d / v
v      ≈ 2e8 m/s   （光纤群速度，约 5 us/km）
```

2 km 光纤：

```
D_prop(2 km) = 10 us
```

若「2 km」是 L1–L2 单段，则 TOR → L2 → TOR 的单向光路约 4 km：

```
D_prop(4 km) = 20 us
```

800G 下单包序列化：

```
D_ser = t_pkt ≈ 42 ns   （相对传播可忽略）
```

商用 NIC / 交换小包处理约 1–2 us。排队 `D_q` 才是乱序的主因。

```
RTT ≈ 2 * D
```

**注意：全路径都是 2 km 只让所有包一起晚 10 us，不制造乱序。乱序只由路径差 `dt` 决定。**

```
dt = dd/v + dD_sw + dD_q
```

`dd` 是同 QP 所用路径的长度差，不是园区最大距离。

### 2.2 不欠吞吐的发送窗口（管道填满）

单 QP 独占端口：

```
W_s >= ceil(B * RTT / P) = N_BDP
```

`N_act` 个 QP 均分端口：

```
W_s(i) >= ceil( (B / N_act) * RTT / P )
```

端口级充要条件（各 QP 发送窗口之和盖住 BDP）：

```
sum_i W_s(i)  >=  N_BDP
```

发窗在硬件里主要是 `snd_una / snd_nxt / cwnd`，每个 QP 几个字，几乎不占 SRAM。真正占 SRAM 的是 outstanding 元数据（PSN、WQE 偏移），大约 16–24 B/包。

### 2.3 乱序接收窗口

逐包打散后，同 QP 包的到达间隔最大为 `dt`：

```
W_r >= ceil(B_qp * dt / P) + 1
```

最坏情况（该 QP 打满端口，`B_qp = B`）：

```
W_r >= ceil(B * dt / P) + 1
```

要同时不欠吞吐、不因超窗重传：

```
W_r >= max( W_s ,  ceil(B_qp * dt / P) + 1 )
```

选择性重传下，位图宽度通常取：

```
W_r >= N_BDP + N_dt
N_dt = ceil(B_qp * dt / P)
```

否则尾包补齐时窗口滑不动，发送端被反压。

### 2.4 带宽、窗口、时延合在一起

不欠吞吐时的可达带宽：

```
B_achieved = min(
    B,
    W_s * P / RTT,
    W_r * P / dt
)
```

第三项含义：收窗不够时，乱序深度把有效窗口卡住，等效按 `dt` 节流。

单流打满端口的充要条件：

```
W_s >= B * RTT / P
W_r >= B * max(RTT, dt) / P
```

多流时把单流公式里的 `B` 换成 `B / N_act`，但端口级仍要满足：

```
sum_i W_s(i) >= B * RTT / P
```

## 3. 2 km、800G 的数值

### 3.1 BDP（由共同走线决定，不制造乱序）

| 口径 | 单向光路 | 加 NIC/交换约 4 us 后的 RTT | N_BDP = B * RTT / P | BDP 字节 |
| --- | ---: | ---: | ---: | ---: |
| 2 km 端到端 | 10 us | 28 us | 670 包 | 2.80 MB |
| 2 km 为 L1–L2 单段 | 20 us | 48 us | 1149 包 | 4.80 MB |

计算示例（2 km 端到端）：

```
RTT    = 28 us
N_BDP  = 100e9 * 28e-6 / 4176 ≈ 670 包
BDP_B  = 100e9 * 28e-6 = 2.80 MB
```

### 3.2 乱序深度（只跟路径差 dt）

单流打满 800G：

```
W_r(dt) = ceil(B * dt / P) + 1
        = ceil(dt / t_pkt) + 1
        = ceil(dt / 41.8 ns) + 1
```

| dt | W_r（单流打满 800G） |
| ---: | ---: |
| 0.5 us | 13 |
| 2 us | 49 |
| 5 us | 121 |
| 10 us | 241 |
| 20 us | 480 |

### 3.3 32K QP 均匀分流时的每 QP BDP

```
B_qp   = 800 Gbit/s / 32768 ≈ 24.4 Mbit/s
N_BDP_qp(28 us) ≈ 0.085 包
```

此时 16–32 包的收窗已经过大。

AI 集合通信通常是**几十到几百个 QP 同时打满**，不是 32K 个一起均分。SRAM 必须按「少数 QP 接近线速」来估。

## 4. 商用 NIC SRAM 口径

公开口径（SRNIC / NSDI’23 及后续引用）：

- Mellanox CX-4/5 片上约 **2 MB**
- 每个 RC QP context 约 **256–375 B**
- CX-6/7 驱动可建 **128K QP**，但片上仍是 cache，多了就走 Host ICM + PCIe
- 实测：并发 QP 过 256 后吞吐开始掉；16K 时 CX-6 从 97 Gb/s 掉到 52 Gb/s

32K QP 的 context：

```
32768 * 375 B = 12.0 MB
```

已超过 2 MB，所以 32K QP 的 QPC **不可能全在片上**。

窗口相关的片上开销：

| 结构 | 每 QP | 32K 全静态 | 能否上片 |
| --- | ---: | ---: | --- |
| 发窗计数（3–4 个 32/64-bit） | ~32 B | 1.0 MB | 可进 QPC |
| OOO 位图 W_r bit | W_r / 8 B | 32K * W_r / 8 | 见第 5 节 |
| IRN 式 5 张 BDP 位图 | 5 * N_BDP / 8 | 极大 | 否 |
| 选择性重传 outstanding 表 | ~24 B * W_s | 极大 | 必须 Host |

800G 代 NIC 片上 SRAM 没有公开数字。按 CX-5 的 2 MB 外推，整卡 4–16 MB、其中能给传输窗口的大约 0.5–2 MB 是合理区间。下面用 **1 MB 窗口预算** 反推，并给出 0.5 / 2 MB 敏感性。

## 5. 反推发送 / 接收窗口

### 5.1 方案 A：32K QP 每条都静态分配相同收窗

```
W_r_max = 8 * M_win / N_qp
```

| 窗口 SRAM `M_win` | 每 QP 位图宽度 `W_r` |
| ---: | ---: |
| 0.5 MB | 128 bit |
| 1.0 MB | 256 bit |
| 2.0 MB | 512 bit |

对应能扛住的单流乱序（800G）：

```
dt_max = W_r * t_pkt
```

| W_r | dt_max | 对比 28 us BDP（670 包） |
| ---: | ---: | --- |
| 128 | 5.3 us | 只有 BDP 的 19% |
| 256 | 10.7 us | 38% |
| 512 | 21.4 us | 76% |

发窗用计数器即可设成 670 或 1149，SRAM 不是瓶颈。  
收窗在静态 32K 分配下只有 128–512 包，**小于端口 BDP（670–1149）**。

收窗不够时的端口上限：

```
B_cap = W_r * P / RTT
```

1 MB、`W_r = 256`、`RTT = 28 us`：

```
B_cap = 256 * 4176 / 28e-6
      = 38.2 GB/s
      = 306 Gbit/s
```

只有 800G 的 **38%**。若按 4 km / 48 us：

```
B_cap = 256 * 4176 / 48e-6
      = 22.3 GB/s
      = 178 Gbit/s   （约 22% 线速）
```

### 5.2 方案 B：共享位图池（MELO / LEFT / ORNIC 一类）

片上只给当前乱序的活跃 QP 分配位图，宽度按端口 BDP：

```
M_pool ≈ N_ooo * W_r / 8
W_r    = N_BDP + N_dt
```

取 `W_r = 1024`（覆盖 48 us BDP + 约 10 us 乱序）：

```
每 QP 位图 = 1024 / 8 = 128 B
1 MB 池   → 8192 个同时乱序的 QP
```

真正线速活跃往往只有几十到几百条，池绰绰有余。此时单流：

```
W_s = W_r = 1024 >= N_BDP
```

**可以打满 800G**，条件是同时处于 OOO 的 QP 数不超过池深。

### 5.3 方案 C：位图 / 重传状态在 Host（SRNIC 一类）

片上几乎只留 QPC cache。32K QP 能建，但每个乱序包可能要 PCIe 读 Host 位图。PCIe 往返约 1–2 us；800G 上 2 us 就是 25 KB ≈ 6 个包的气泡。乱序率低时能打满；持续逐包打散时 Host 路径会成为瓶颈。

## 6. 能否打满：判定表

前提：选择性重传 + OOO 直接落位（不是 Go-Back-N）。

| 实现 | 32K QP 均分 | 少量 QP 线速 + 逐包打散 | 依据 |
| --- | --- | --- | --- |
| 静态每 QP 128–256 bit 收窗 | 能 | 不能（约 22%–38% 线速） | W_r < N_BDP |
| 共享 BDP 位图池（约 1 MB） | 能 | 能 | W_r >= N_BDP |
| Host 位图 | 能 | 乱序持续时危险 | PCIe 抢 800G 预算 |
| 经典 RoCE GBN、无 OOO 窗 | 能（有序 ECMP） | 不能（超窗即重传塌缩） | GBN 放大 |

**按典型商用 NIC（片上数 MB、QPC cache、32K 并发）的默认静态资源：发窗够，收窗不够。**

800G × 28 us 要 670 包的收窗才能单流填满管道；均分到 32K QP 后每条只剩 128–256 包，只能覆盖 5–11 us 的乱序，覆盖不了 2 km 对应的 BDP。

三条结论：

1. **只问端口打满、32K QP 同时干活**：能打满，窗口不是瓶颈。
2. **问逐包打散且允许单 QP / 少 QP 跑满 800G**：典型静态 SRAM 打不满，需要共享位图池，或把真正活跃的 QP 限制在几百以内并给它们 BDP 级收窗。
3. **2 km 走线**：把 RTT / BDP 加大（670 → 约 1150 包，若 2 km 是单段），不增加乱序；乱序预算仍按 `dt` 单独给。

工程验收：

```
W_r_shared  >=  B * RTT / P  +  B * dt_p99.9 / P
```

800G、`RTT = 28 us`、`dt_p99.9 = 10 us`：

```
W_r >= 670 + 240 = 910 包
```

1 MB 共享池按 1024 bit/QP 可同时支撑约 8000 条乱序连接，对集合通信足够；32K 条各静态 256 bit **不够**支撑线速逐包打散。

## 7. 公式速查

```
# 时延
D      = D_prop + D_ser + D_sw + D_nic + D_q
D_prop = d / v                          # v ≈ 2e8 m/s
RTT    ≈ 2 * D
dt     = dd/v + dD_sw + dD_q            # 乱序只看路径差

# 包时
t_pkt  = P / B
N_BDP  = ceil(B * RTT / P)

# 发窗（不欠吞吐）
W_s           >= N_BDP                  # 单流打满
W_s(i)        >= ceil(B/N_act * RTT / P)
sum_i W_s(i)  >= N_BDP                  # 端口级

# 收窗（逐包打散）
W_r >= ceil(B_qp * dt / P) + 1
W_r >= max(W_s, N_BDP + N_dt)           # 同时不欠吞吐、不超窗

# 可达带宽
B_achieved = min(B,  W_s*P/RTT,  W_r*P/dt)

# 静态 32K 分配能给出的收窗
W_r_max = 8 * M_win / N_qp

# 收窗不够时的端口上限
B_cap = W_r * P / RTT
```

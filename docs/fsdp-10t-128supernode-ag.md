# 10T DeepSeek、128 卡超节点、约 10 万卡：FSDP 通信域与参数 all-gather

结论先写在这里。按前面已经定下的硬件，每层参数 all-gather 留在 128 卡超节点内，不进参数面。进参数面的是流水线阶段之间的激活，以及数据并行副本之间每步一次的梯度 all-reduce。路由专家不做参数 all-gather。

640 GB 不参与这次计算。它只在 10T 外推表里用来算 FP4 专家表的容量下限：4.975 TB / 640 GB，向上取整得 8 张卡。同一份时延分析写明，后面改用 96 GB、128 卡超节点。

## 1. 模型，沿用 1T→10T 外推

骨架是 V4-Pro。10T 这一档只增加路由专家个数，层数、隐藏维、专家中间维、每 token 激活的专家个数不动。下面这些数来自 `docs/deepseek-1t-10t-arch.md`，1.6T 是论文原模型，10T 是外推。

| 符号 | 含义 | 取值 |
| --- | --- | --- |
| L | 层数 | 61 |
| H | 隐藏维 | 7168 |
| I | 专家中间维 | 3072 |
| E | 路由专家个数 | 2469 |
| K | 每 token 激活的路由专家 | 6 |
| P_other | 注意力、共享专家、词表、mHC、MTP | 5.260×10^10 |

一个路由专家在全部层上的参数，SwiGLU 三矩阵：

```text
P_one = 3 × H × I × L
      = 3 × 7168 × 3072 × 61
      = 4.030×10^9
```

逐项：

```text
7168 × 3072 = 22,020,096
3 × 22,020,096 = 66,060,288          单层一个专家
66,060,288 × 61 = 4,029,677,568      全层一个专家，记作 4.030×10^9
```

10T 路由专家总参数：

```text
P_routed = E × P_one
         = 2469 × 4.030×10^9
         = 9.950×10^12
```

加上非路由的 5.260×10^10，总数约 1.000×10^13。

单层全部路由专家的参数：

```text
P_layer = E × 3 × H × I
        = 2469 × 66,060,288
        = 1.631×10^11
```

全层专家训练态若按每参数 16 字节，单层是：

```text
P_layer × 16 = 2.610×10^12 字节 = 2.610 TB
```

非路由参数里，共享专家与一个路由专家同形，全层 4.030×10^9。其余约 4.857×10^10 是注意力、词表、mHC、MTP。

单 token、全层的专家通信量沿用原文恒等式，不另测：

```text
B_tok = K × 3 × H × L
      = 6 × 3 × 7168 × 61
      = 7.87×10^6 字节
```

其中 `3 × H` 是 FP8 dispatch 与 BF16 combine 的口径，来自前面的外推备注。单层是 `6 × 3 × 7168 = 129,024` 字节，约 126 KB。

## 2. 硬件，沿用时延分析里的集群

时延分析页写的是：

| 项目 | 取值 |
| --- | --- |
| 每卡 HBM | 96×10^9 字节 |
| HBM 带宽 | 峰值 4 TB/s，按 80% 取有效 3.2 TB/s |
| 超节点 | 128 卡 |
| 超节点内 D2D | 有效 320 GB/s |
| 参数面 | 每卡有效 40 GB/s |
| 主机到卡 | 64 GB/s × 80% = 51.2 GB/s |

超节点显存：

```text
128 × 96×10^9 = 1.229×10^13 字节 = 12.29 TB
```

10 万不能被 128 整除。

```text
780 × 128 = 99,840
781 × 128 = 99,968
```

下面按 780 个超节点、99840 卡切。多出来的卡不进这个整除方案。

推理页的摆法是一份模型 EP=128，铺满一个超节点。那是 FP4 权重：

```text
单专家 FP4 = 4.030×10^9 × 1/2 = 2.015×10^9 字节 = 2.015 GB
每卡专家数 = 2469 / 128 = 19.3
每卡 FP4 路由权重 = 19.3 × 2.015 = 38.9 GB
```

4.975 TB 的专家表放得进 12.29 TB。训练要另算，因为优化器状态比 FP4 权重大一个数量级。

## 3. 训练态按每参数 16 字节估算

这个 16 字节不是论文里的数，是混合精度 Adam 的常用拆分，用来判断通信域，不代表某个框架的实际字节数。

```text
BF16 权重 2 + BF16 梯度 2 + FP32 主权重 4 + 动量 4 + 方差 4 = 16 字节/参数
```

路由专家：

```text
S_routed = 9.950×10^12 × 16 = 1.592×10^14 字节 = 159.2 TB
```

非路由：

```text
S_other = 5.260×10^10 × 16 = 8.416×10^11 字节 = 0.842 TB
```

合计约 160 TB。一个超节点只有 12.29 TB，装不下整模的训练态。

单层路由专家训练态 2.610 TB。一个超节点按显存能装的层数：

```text
12.29 / 2.610 = 4.7 层     训练态占满 HBM 的上限
6.14 / 2.610 = 2.4 层      只拿一半 HBM 给专家训练态
```

非路由 0.842 TB 摊到 61 层，每层约 14 GB，相对 2.610 TB 可以先不占这个层数。激活、临时缓冲要从剩下的显存里出，所以按 4 层去排会把余量吃紧。下面用每超节点 2 层专家，训练态 5.22 TB，占该超节点 HBM 的 42%。

## 4. 通信域

61 是质数，流水线不能把层数切成相等的若干段，除非一段一层。一段一层时，一条流水线要 61 个超节点，780 不能被 61 整除。

改成不等长：29 个超节点各放 2 层，1 个超节点放 3 层。

```text
29 × 2 + 3 = 61
阶段数 = 30
副本数 = 780 / 30 = 26
```

`26 × 30 = 780`，卡数 `780 × 128 = 99840`。

每个超节点内部沿用推理页的切法，只是作用从推理权重变成这一阶段的训练态：

| 通信域 | 规模 | 网络 | 每步做什么 |
| --- | --- | --- | --- |
| TP | 8 | 超节点内 D2D | 注意力激活 all-reduce，每层 |
| DP 内层 | 16 | 超节点内，与 TP 合成 128 卡 | 非路由参数的 FSDP 分片 |
| EP | 128 | 超节点内 D2D，有效 320 GB/s | 本阶段专家常驻，token all-to-all |
| PP | 30 段 | 参数面，点对点 | 段间传激活 |
| DP 外层 | 26 个副本 | 参数面 | 每步一次梯度 all-reduce |

2 层阶段的专家训练态 5.22 TB，3 层阶段 7.83 TB，都低于 12.29 TB。EP 不用跨出超节点。

## 5. 参数 all-gather 进不进参数面

不进。

要 all-gather 的是非路由参数。它们被 FSDP 切在 128 卡里面。一个共享专家单层 BF16 权重：

```text
66,060,288 × 2 = 1.321×10^8 字节 = 132 MB
```

按超节点 D2D 有效 320 GB/s 估算，这一次 all-gather 约 0.4 毫秒。61 层、前向加反向，共享专家这一项约 50 毫秒量级，并且可以和计算重叠。注意力、词表的 all-gather 同样只在这 128 卡内。

路由专家不参与这次 all-gather。每张卡只保存自己的专家。推理页的每卡 19.3 个专家，到训练里仍然是这 128 卡把本阶段的 2469 个专家分完，专家权重在前向之前已经在卡上。

如果改成每层把全部路由专家 all-gather 一次，单层 BF16 权重是：

```text
1.631×10^11 × 2 = 3.26×10^11 字节 = 326 GB
```

61 层、前向加反向，每步约 40 TB 的拼参流量。这不是可选项。所以专家走 EP 常驻，不走 FSDP 的参数 all-gather。

对照：同一笔 326 GB 若放到参数面、按每卡 40 GB/s 去搬，单层就要数秒。域划在超节点内，用的是 320 GB/s 的 D2D，而不是 40 GB/s 的参数面。

## 6. 参数面上实际有的流量

### 6.1 段间激活

一个 micro-batch 的一个 token，过一次段边界，BF16 隐藏状态：

```text
H × 2 = 7168 × 2 = 14,336 字节
```

一条链有 29 个段边界。全局批量、序列长度要另外给定，这里不代填。

### 6.2 专家梯度的 all-reduce

这是梯度，不是参数 all-gather。26 个副本之间，每步一次。

本阶段专家在一张卡上的 BF16 梯度，按 EP=128、每卡 19.3 个专家、每个专家单层 132 MB：

```text
2 层：19.3 × 132 MB × 2 = 5.10 GB
3 层：19.3 × 132 MB × 3 = 7.65 GB
```

环形 all-reduce 每卡搬的数据约两倍梯度：

```text
2 层：约 10.2 GB/卡
3 层：约 15.3 GB/卡
```

除以参数面每卡 40 GB/s：

```text
2 层：10.2 / 40 = 0.26 秒
3 层：15.3 / 40 = 0.38 秒
```

这是每步一次，不是每层一次。非路由梯度整模 BF16 只有 `5.260×10^10 × 2 = 105 GB`，再按本阶段层数和 128 卡切开，每卡远小于专家梯度。

### 6.3 token all-to-all

本方案里一个阶段的 2469 个专家都在同一个超节点，all-to-all 走 D2D，不进参数面。单层每 token 126 KB，除以 320 GB/s，单 token 这一层约 0.4 微秒；批量上来以后按最忙卡的发出量除以 320 GB/s。

只有专家训练态超过一个超节点时，all-to-all 才进参数面。装不下的判据：

```text
本阶段专家训练态 = 层数 × 2.610 TB
超节点显存 = 12.29 TB
```

2 层、3 层都低于 12.29 TB。再留激活时，2 层仍只占 42% 的 HBM。

## 7. 和 640 GB 那句话的边界

640 GB 只回答「FP4 专家表最少几张卡能放下」。10T 是 8 张，1.6T 是 2 张。它不描述这个 10 万卡集群的 HBM，也不描述训练态。训练态用 96 GB × 128 卡重算之后，参数 all-gather 的落点是超节点内的 D2D。
